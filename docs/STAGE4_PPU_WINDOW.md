# DMG-окно: LCDC.5 и позднее совпадение WX

Исходники восстановлены 18 октября 2026 из исходного commit `be634cd53f80b56dae9d9db41cb9a5d28bd19ce4`. Сравнение продолжает использовать прежний эталон `m3_lcdc_win_en_change_multiple_wx_dmg_blob.png`; ROM и выбор физического эталона не изменены.

## Исправления

На DMG отключение окна теперь проверяется в момент чтения индекса тайла из VRAM (`GET_TILE_T2`), одновременно с выбором карты. Раньше состояние окна фиксировалось на предыдущем dot (`GET_TILE_T1`), поэтому запись LCDC.5 на границе этих фаз оставляла лишний тайл окна. Фазы CGB не изменены.

Позднее совпадение WX по `position_in_line + 6` по-прежнему активирует окно. Убрано дополнительное уменьшение LCD X, которое сдвигало вывод на один пиксель и перезаписывало предыдущий экранный пиксель. Это соответствует выбранному LCD-профилю DMG-blob.

Это исправление окна не добавляет полей состояния и точек продолжения PPU. Отдельное исправление CGB TILE_SEL добавляет регистр физической шины `last_tile_data_bus` и повышает общую внутреннюю версию состояния до 18; импорт старых версий идёт через BESS с потерей точных фаз PPU.

## Физические варианты DMG

В наборе есть два физических эталона этой ROM: `dmg_b` и `dmg_blob`. Они различаются на 3 пикселя. Исходный комментарий SameBoy описывает рассинхронизацию LCD при позднем WX как свойство части экземпляров DMG, не привязанное однозначно к ревизии CPU.

Только перенос проверки LCDC.5 на `GET_TILE_T2` соответствует варианту с LCD-сдвигом `dmg_b`. Окончательный вариант выбирает LCD-поведение без такого сдвига и проверяется по `dmg_blob`. Имя внутренней модели CPU `GB_MODEL_DMG_B` само по себе не задаёт вариант LCD.

Существующий runner всегда предпочитал `dmg_blob` при наличии такого эталона; этот выбор не изменён. Другая ROM с двумя физическими эталонами, `m3_lcdc_bg_en_change`, уже была настроена на `dmg_blob` до этого исправления. Совпадение со всеми эталонами другого физического экземпляра `dmg_b` не заявляется.

## Состояния PPU

Свежий запуск 18 октября после восстановления исходников: [stage4-ppu-state-tests.txt](stage4-ppu-state-tests.txt). Проверены сохранение до/после OBJ-latch на DMG/CGB C/D, отдельные значения физической шины `$33` и пиксельного latch `$AA` после TILE_SEL-глитча, точное продолжение после сохранения, равенство шины и изображения быстрого/пошагового PPU при SCX 0–7 и горизонтальном отражении, BESS fallback и отклонение native-состояния старой версии без BESS.

Настоящий fixture версии 17 заново получен из нетронутого старого ядра и побайтно совпадает с ранее созданным. Происхождение, исходник генератора и SHA256 описаны в [README fixtures](../tests/fixtures/README.md). Тесты с тегами v16/v17 в новом снимке помечены как синтетические и не выдаются за проверку реального старого формата v16.
