# GameBoy Studio — этап 3: скорость игр

15 октября 2026, Windows 10 x64. По сообщению об ускорении приоритет этого этапа перенесён на темп игры. Исправлено накопление ускоренного времени после отпускания Turbo и добавлен явный возврат к 1×. **Постоянное ускорение на доступных тестовых ROM не воспроизвелось; исправление всех возможных причин не заявляется.** Название проблемной игры и точный коэффициент ускорения пока неизвестны.

## Что изменено

- При отпускании Turbo, выборе скорости, паузе, сбросе, смене ROM и восстановлении фокуса сбрасывается накопленное время. Выбор 1× также снимает активный Turbo.
- После задержки Windows на 1× выполняется максимум два догоняющих кадра за вызов таймера. Дробная часть времени сохраняется, чтобы обычный jitter не замедлял игру. Лимит растёт с выбранным ускорением.
- Ctrl+0 возвращает обычную скорость. Пользовательские назначения клавиш имеют приоритет; если Ctrl+0 переназначено, выберите 1× в меню времени.
- Заголовок и нижняя строка показывают выбранную скорость; нижняя строка дополнительно показывает измеренный темп в процентах. В норме ожидаются примерно 1×, 100% и 59,73 FPS. Процент появляется после первого интервала измерения; небольшие колебания допустимы.
- В диагностический JSON добавлены выбранная скорость, Turbo, пауза, частота вызовов кадров и базовая частота ядра. Добавлен режим замера через настоящий цикл WM_TIMER.
- Защита от вложенного вызова таймера предотвращает повторное исполнение во время модальных обработчиков. Сброс при отпускании Turbo выполняется только когда Turbo действительно активен — обычная игровая клавиша при сочетании вроде Ctrl+Z не теряет время.

## Проверки готового EXE

Три собственных ROM проверяют DMG, обычный CGB и CGB с настоящим переключением KEY1/STOP. Каждый запускается отдельно пять секунд, со звуком и без. Измеряются реальные секунды, базовые такты и счётчик кадров PPU. Допуск отношения времени — 0,97–1,03; дополнительно проверяются частота PPU, режим CPU, 1×, выключенный Turbo и лимит двух кадров. Во всех звуковых случаях открылся WASAPI.

| ROM | Звук | Реальные секунды | Эмулированные секунды | Темп | PPU FPS | Результат |
|---|---|---:|---:|---:|---:|---|
| dmg-normal | выключен | 5.0143 | 4.9893 | 99.50% | 59.43 | PASS |
| cgb-normal | выключен | 5.0020 | 4.9726 | 99.41% | 59.38 | PASS |
| cgb-double | выключен | 5.0046 | 4.9726 | 99.36% | 59.35 | PASS |
| dmg-normal | WASAPI | 5.0128 | 4.9893 | 99.53% | 59.45 | PASS |
| cgb-normal | WASAPI | 5.0109 | 4.9726 | 99.23% | 59.27 | PASS |
| cgb-double | WASAPI | 5.0040 | 4.9726 | 99.37% | 59.35 | PASS |

Итого **6/6 PASS**, темп 99.23–99.53%. Это измерение скрытого Win32-окна с тем же планировщиком и ядром; GPU-показ и слышимое качество звука им не проверяются.

Независимый замер ядра: во всех трёх режимах 600 вызовов кадра дают 42 134 400 базовых тактов и 600 кадров PPU. При CGB double speed CPU выполняет вдвое больше инструкций, но базовая частота остаётся 4 194 304 Гц, а видеочастота — около 59,73 Гц. Принудительно замедлять CGB double speed не требуется.

Новый C++-тест планировщика прошёл напрямую и через CTest: моделируются 60/144/240 Гц с jitter, скорости 0,25×–16×, остановка Windows на 150 мс, переходы Turbo/паузы и неверные значения времени. Основной Windows QA — **3/3 PASS**: CPU rendering self-test и DMG/CGB-демо по 600 кадров, 160×144.

## Как проверить у себя

Распакуйте весь архив и запустите `START_WINDOWS.bat`. После загрузки игры нажмите Ctrl+0 либо выберите обычную скорость 1× в меню времени. Подождите несколько секунд и посмотрите темп в нижней строке. При 1× около 100% обычный темп подтверждается счётчиком планировщика; если конкретная игра всё ещё кажется быстрой, диагностический отчёт сохранит настройки и хеш ROM для дальнейшего разбора.

Для разработчика, из корня исходников:

```text
python tests/run_timing_tests.py --emulator dist/GBStudio.exe --output build/timing-no-audio --report build/timing-no-audio.json --seconds 5
python tests/run_timing_tests.py --emulator dist/GBStudio.exe --output build/timing-audio --report build/timing-audio.json --seconds 5 --audio
ctest --test-dir build -C Release -R frame_pacing --output-on-failure
```

Для одной своей ROM: `dist/GBStudio.exe --timing-test report.json --timing-seconds 5 --timing-audio game.gbc`. Режим скрывает окно, принудительно использует 1× и не загружает пользовательские настройки/сессию. Звук без `--timing-audio` не открывается. Это диагностический режим; обычный запуск не требует Python.

## Что осталось

Ядро, headless и фильтры побайтно совпадают с этапом 2. Версии C ABI 3 и внутренних состояний 17 сохранены. Полные Mealybug/SameSuite на этом этапе повторно не запускались: исторический результат этапа 2 — **64 PASS / 7 FAIL Mealybug, 78/78 SameSuite**, три Boot-проверки остаются открытыми. Следующая группа PPU — `m3_lcdc_tile_sel_change` и `m3_lcdc_tile_sel_win_change` на CGB C/D.

Реальные игры, полная проверка GUI/GPU и устройств, оригинальные Boot ROM, LAN/WAN, серверный Hardcore и цифровая подпись остаются неподтверждёнными. Нажатия физических клавиш и слышимое качество аудио в этом этапе отдельно не проверялись. Удалённый GitHub Actions и Linux/sanitizer-сборки здесь не выполнялись.

Актуальные измерения: `stage3-validation.json`, `stage3-timing-no-audio.json`, `stage3-timing-audio.json`, `stage3-core-speed.json`, `stage3-windows-qa.json`. Предыдущие отчёты сохранены. SHA256 EXE: `f2ebd88c24037246a60bd7ea80929b6c776b676125eddf54ac49d7d38f5de6c0`.
