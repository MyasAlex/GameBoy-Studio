# GameBoy Studio 1.1 — собственное ядро Studio

[Скачать готовую версию 1.1 для Windows](https://github.com/MyasAlex/GameBoy-Studio/releases/tag/v1.1.0). В Assets выберите **GameBoy-Studio-1.1.0.zip**; автоматические архивы Source code содержат только исходники.

В этой версии единственное ядро эмуляции — **собственное C++-ядро Studio**. CPU и память находятся в `src/gameboy.hpp`, LCD — в `src/native_ppu.hpp`, звук — в `src/native_apu.hpp`. Эти исходники собираются вместе с приложением и консольным запускателем. SameBoy, его загрузочной прошивки и `gb_accuracy.dll` в этой версии нет. Существующая MIT-лицензия проекта и сведения об авторах сохранены.

В архиве исходники, готовая Windows x64-сборка в `dist` и два собственных homebrew-демо. Для запуска полностью распакуйте архив и откройте `START_WINDOWS.bat` или `dist\GBStudio.exe`; компилятор для этого не нужен. Отчёт текущих проверок — `docs/native-validation.json`; старые отчёты прежней версии не являются результатами этого ядра.

## Пересборка Windows

1. Распакуйте весь архив.
2. Установите Visual Studio с компонентами **Desktop development with C++** и **CMake tools**.
3. Запустите `BUILD_WINDOWS.bat --no-launch` либо откройте `GBStudio.sln` и выполните сборку.
4. После успешных тестов откройте `START_WINDOWS.bat` или `dist\GBStudio.exe`.

Скрипт собирает проект из исходников, запускает тесты и устанавливает результат в `dist`. DLL эмулятора не требуется. Отдельный `gb_pixel_filters.exe` используется для xBRZ, а Lua, miniz и rcheevos собираются из включённых исходников. Готовую папку `dist` можно переносить целиком; для её запуска компилятор уже не нужен.

Открыть свою игру: Ctrl+O или перетащить `.gb`, `.gbc`, `.zip`, `.gz` на окно. Коммерческие игры и оригинальные Nintendo Boot ROM в архив не включены. Внешняя загрузочная ROM необязательна: по умолчанию ядро начинает с собственного состояния после загрузки.

## Управление

| Действие | Клавиши по умолчанию |
|---|---|
| Игрок 1 | Стрелки, Z/X, Shift/Enter |
| Игрок 2 при Link | WASD, G/H, T/Y |
| MBC7: наклон | Num4/6, Num8/2; правый стик XInput |
| Пауза / сохранение / загрузка / кадр | P / F5 / F9 / F6 |
| Полный экран / снимок BMP | F11 / F12 |
| Перемотка / turbo | Удерживать Backspace / Tab |
| Обычная скорость 1× | Ctrl+0 или меню скорости |
| CPU Studio | Ctrl+D |

Кнопки и горячие клавиши переназначаются в меню. Пользовательское назначение Ctrl+0 имеет приоритет. Слоты выбираются клавишами 1–9.

## Что реализовано и что ограничено

Ядро содержит CPU DMG/CGB, таймеры, DMA/HDMA, банковую память, LCD-конвейер, четыре звуковых канала и serial Link. Поддерживаются ROM-only, MBC1/2/3/5/7, HuC1 и Game Boy Camera. Сохраняются RAM и MBC3 RTC; MBC7 включает интерфейс наклона и EEPROM. Printer обрабатывается инструментами Studio.

MMM01, MBC6 и HuC3 не реализованы. SGB HLE, команды Super Game Boy и рамки отсутствуют. Названия аппаратных профилей в интерфейсе не означают точную эмуляцию каждой электрической ревизии: основа ядра — семейства DMG и CGB. Совместимость цветных игр с выбранной консолью проверяется при загрузке.

В приложении сохранены отладчик, просмотр памяти/тайлов/OAM/палитр, читы и поиск RAM, rewind, BESS, TAS, редактор временной шкалы, локальный Link, сетевые инструменты, Lua, библиотека игр, аудио/видеозапись и эффекты изображения. Наличие инструмента не подтверждает совместимость всех игр или устройств. Проверка Windows GUI, GPU, реального звука, геймпадов, камеры, WAN и официального RetroAchievements требует отдельного прогона.

Для Link вторая ROM хранит данные отдельно в Player2. В сети обе стороны должны использовать одинаковую версию и одинаковые ROM в одинаковом порядке. Между разными ядрами обмен состояниями и точный replay не поддерживаются. Реальные обмены Pokémon и физические аксессуары не считаются проверенными.

## Сохранения

Перед переходом сохраните копию старой папки программы и своих данных.

- Батарейная RAM — `.sav`; часы MBC3 — `.rtc`. Копируйте оба файла, если у игры есть RTC.
- Новые собственные снимки — GBSTATE8; BESS использует Studio GBSP3 и при необходимости GBAU для прогресса инструментов. Они сохраняют дополнительные фазы LCD/APU и аппаратный профиль.
- GBSTATE3–7 и GBSP2 продолжают читаться. В них нет новых фаз: при импорте они восстанавливаются приближённо. Для точного продолжения современного снимка нужны совместимая сборка и тот же аппаратный профиль.
- Снимки прежнего ядра SameBoy (`GBSACC1`, `GSTU`/`GBSX`) и его TAS нельзя считать совместимыми с точным продолжением Studio. Обычный BESS может импортироваться с потерей внутренних фаз; обмен с каждым сторонним эмулятором не гарантирован.
- Файлы `.sbbattery` прежней версии это ядро не использует. Обычная `.sav` может содержать подходящую RAM, но перенос RTC из `.sbbattery` автоматически не выполняется.

Настройки хранятся рядом с EXE либо в LocalAppData при отсутствии прав записи. Распакованные ROM находятся в ArchiveCache; данные инструментов — в Games по хешу игры. Личные ROM, аккаунты и сохранения не входят в поставку.

## Проверка из исходников

```text
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
build/gb_headless demo.gb --frames 120 --output demo.ppm
```

Для генератора Visual Studio используйте `cmake --build build --config Release`, `ctest --test-dir build -C Release --output-on-failure` и `build\Release\gb_headless.exe`. Скрипт `BUILD_WINDOWS.bat` делает это автоматически.

Аппаратные ROM-тесты можно запускать отдельно через `tests/run_rom_tests.py`, `tests/run_cgb_tests.py` и `tests/run_extended_tests.py`. Они проверяют поведение, а не меняют авторство кода. Все реальные FAIL и TIMEOUT должны оставаться в отчётах. Старые проценты успешности прежней SameBoy-сборки не относятся к этой версии. Универсальная «100% работоспособность» не заявляется.
